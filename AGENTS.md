# Web development rules

- Read the existing project structure and documentation before changing code.
- Preserve working design decisions; do not add dependencies without a concrete need.
- Validate responsive behavior at mobile and desktop sizes.
- Prefer semantic HTML, keyboard navigation, visible focus, sufficient contrast, and `prefers-reduced-motion`.
- Keep animations purposeful and favor transform/opacity for frequent motion.
- Run the project's lint, typecheck, build, and relevant tests before handoff.
- Check for horizontal overflow, console errors, broken links, and network failures when browser tooling is available.
- Update documentation when architecture or important decisions change.
